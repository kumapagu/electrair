更新日：2026年11月19日（日本時間）

既存の実装引継ぎ資料0.6版からの整理。今回の移行は仕様変更・個別作業の承認を意味しない。段階2の候補は採用決定まで初回の実装対象に含めない。

### 機能が正しく動くかの確認

以下のうち、段階1はP01〜P05・P07・P09・P11〜P14を対象とする。P06はまず1台で必須写真不足を検証し、複数台の判定は段階2で行う。P08・P10は段階2で機能を採用した場合に確認する。未採用の項目は未実装・未確認として残す。

| ID | 操作 | 期待する結果 |
| --- | --- | --- |
| P01 | 未割当案件に日時・担当を設定 | 未割当から外れ、対応する担当・日の予定に表示される |
| P02 | 同じ担当の重複時間に別案件を割当 | 重複する案件名を表示して保存を止める |
| P03 | 予定の担当または日付を変更 | 元の枠から外れ、変更先と作業員の案件一覧に反映される |
| P04 | 作業員を切替 | 選択した作業員の案件のみが表示される |
| P05 | 写真・メモを下書き保存して再読込 | 写真・入力内容が保持され、提出扱いにならない |
| P06 | 複数台のうち1台の必須写真が不足したまま提出 | 不足する機器と写真区分を表示して提出を止める |
| P07 | 必須内容を揃えて完了報告を提出 | 工事が完了、報告が確認待ちになり、社長の一覧に現れる |
| P08 | 社長が理由付きで差し戻し、作業員が修正・再提出 | 理由が作業員側に表示され、再提出後に確認待ちになる |
| P09 | 社長が確認済みにする | 確認待ちから外れ、確認済み一覧に移る |
| P10 | 再訪問理由と対応を入力して提出 | 工事は再訪問が必要、報告は確認待ちとして別々に表示される |
| P11 | 終了日時を過ぎても未提出の案件を確認 | 未報告一覧に表示され、提出済みの案件は混ざらない |
| P12 | 幅390px程度の表示とiPhone実機で管理・報告操作 | 日程・担当変更、報告確認、写真追加・提出を横スクロールに頼らず行える。PC表示と実機確認の結果は別に記録 |
| P13 | 非対応画像・容量超過・保存失敗 | 理由が表示され、保存できたと誤認させない |
| P14 | リセットを実行 | 確認後に変更内容が消え、初期サンプルに戻る |

ブラウザ操作による確認を中心とし、割当の重複判定と状態遷移は独立して検証する。実際に確認できた範囲と未確認項目を実装完了時に記録する。
