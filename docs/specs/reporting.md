# 案件確認・報告の仕様

更新日：2026年11月19日（日本時間）

既存の実装引継ぎ資料0.6版からの整理。今回の移行は仕様変更・個別作業の承認を意味しない。段階2の候補は採用決定まで初回の実装対象に含めない。

### 現場報告

- 写真は案件内の機器ごとに整理する。複数台分を同じ写真欄に混在させない。
- 初回の写真区分は「施工前」「施工後」「その他」。施工前・施工後を各1枚以上必須とし、その他は任意とする。機器ラベル等の詳細区分は後続で検討する。
- 段階2で採用する場合、チェック項目は「試運転」「水漏れ確認」を仮置きし、各項目を「確認済み／問題あり／対象外」で記録。問題あり・対象外は理由を必須とする。
- 上記は操作検証用であり、実際の施工手順・安全基準・元請け指定を網羅するものではない。詳細テンプレートは実務確認後に決める。
- 段階1の作業結果は「完了」。段階2で採用する場合に「再訪問が必要」を追加し、理由と次回対応を必須にする。
- 作業結果を選択するまでは下書きとして扱う。再訪問が必要な場合も、その回の報告を提出できる。
- 段階2で採用する場合、追加内容は「なし／あり」で明示。ありの場合は内容を必須にし、金額・承認状況・精算先は任意メモとする。請求金額は自動計算しない。
- 型番・製造番号は任意。未入力でも提出可能とし、入力負担を検証する。
- 条件不足時は提出を止め、不足する機器と項目を具体的に表示。下書きは保存可能。
- 提出後は作業員の編集を止める。差し戻し後に再編集・再提出できる。

### 社長による確認

- 未報告は「予定終了日時を過ぎ、まだ一度も提出されていない案件」。現在時刻に基づいて一覧から抽出する。
- 確認待ちの報告のみ、確認済みまたは差し戻しに変更できる。
- 差し戻し理由は必須。作業員画面にも表示する。
- 確認済みは「報告を確認した」状態であり、元請けへの報告済み・請求済みを意味しない。

## 状態の持ち方

段階1は工事の「未手配／予定済み／完了」と報告の「未提出／確認待ち／確認済み」を扱う。再訪問・差し戻しの状態と操作は段階2の採用判断に従う。

| 軸 | 状態 | 意味 |
| --- | --- | --- |
| 工事 | 未手配 | 日時・担当のいずれかが未設定 |
| 工事 | 予定済み | 日時・担当が設定済み |
| 工事 | 完了 | 作業員が完了結果を報告として提出 |
| 工事 | 再訪問が必要 | 作業員が理由・次回対応とともに報告として提出 |
| 報告 | 未提出 | 未入力または下書き段階 |
| 報告 | 確認待ち | 作業員が提出済み |
| 報告 | 差し戻し | 社長が理由付きで修正を依頼 |
| 報告 | 確認済み | 社長が内容を確認済み |

報告の遷移は `未提出 → 確認待ち → 確認済み`、または `確認待ち → 差し戻し → 確認待ち`。差し戻しだけで工事を未完了に戻さない。再訪問の日程化や複数回の訪問履歴は初版では対象外とし、次回対応メモまで扱う。
