# design-task

プロジェクトルートを基準にパスを解決し、AGENTS.md、docs/development-workflow.md、docs/tasks/README.md、対象作業記録を読む。手順から仕様や承認を新設・上書きしない。結果は対象作業記録へ残す。

## 手順

1. ①の対象版・承認範囲を確認する。未承認なら①の確認資料までに留める。
2. 対象仕様、docs/design-guidelines.md、採用済みADRを読み、ルール・状態遷移・データ・画面導線と保存失敗時の動作を整理する。既存方針と新提案を区別する。
3. 予定・割当と作業・報告の代表画面を、設計確認に必要な最小の環境で用意する。サンプルや未接続の処理を明示し、スマホ優先とPCの表示を確認する。
4. ロジック、部品、保存連携、ブラウザ、iPhone実機の検証分担とP番号との対応を決める。重要な判断をdocs/adr/template.mdで起案する。
5. ①を変更する内容は①の該当部分の再確認を先に行う。設計の対象版・判断点を揃えて②の承認を求め、実際の判断を記録する。
6. 設計承認前に本格的な機能実装を開始しない。軽微な内部設計の判断をすべて人間承認にしない。

成果物は仕様・設計への参照、操作可能な代表画面、検証方針、ADR案、②の確認資料とする。
