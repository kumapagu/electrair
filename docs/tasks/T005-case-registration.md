## ① 作業定義

管理者が新しく受けた工事依頼を自分で登録し、一覧から見つけて既存の予定・担当の割当へ進めるようにする。利用者検証ではH01の日程・担当判断の前段から試せる。[案件登録の既存案](../specs/scheduling.md#案件登録)・[画面構成](../specs/overview.md#画面構成)

### 範囲と判断点

- **一覧の範囲。** 推奨案は管理者に「案件一覧」（A02）を設け、サンプル案件と新規案件を表示すること。新規案件は既存の「予定・割当」の未割当欄にも反映する。既存の未割当欄だけを使う案なら画面追加は少なく、割当後の案件は担当別予定から探すことになる。
- **登録の範囲。** 既存案に沿い、元請けと現場名を仮登録の必須項目とする。住所は登録時に任意で入力でき、予定の確定までに補完できる範囲を含める。住所の補完場所とその他の任意項目は②で決める。[既存の割当ルール](../specs/scheduling.md#日程担当の割当)
- **今回の対象外。** 検索・絞込、一般的な案件編集・削除、複数台、差し戻し、再訪問、外部取り込み、端末間共有。登録には架空の情報を使い、[ADR-0001](../adr/0001-local-storage-and-role-preview.md)のブラウザ内保存と疑似役割切替を適用する。

## ② 設計

### 画面と業務ルール

| 画面 | 操作と結果 |
| --- | --- |
| 管理者の案件一覧（A02） | 「新規案件を登録」でフォームを開く。保存成功後はフォームを閉じ、登録した案件を一覧の先頭に表示する。既存のサンプル案件と割当済み・完了済みの案件も表示し、現場名、元請け、工事と報告の状態、日程・担当を見られるようにする。未割当カードの「日時・担当を設定」から割当へ進める。 |
| 新規登録フォーム | 元請けと現場名は必須のテキスト入力、現場住所と依頼メモは任意。前後の空白を除き、空白のみの必須入力は不足として扱う。同名の現場でも別の工事依頼を登録できる。保存中は重ねて送信できないようにし、失敗時はフォームと入力値を保持して理由を表示する。 |
| 予定・割当（A01） | 登録直後の案件は「未割当案件」に表示する。住所が空の場合だけ、A01・A02から共通で開く割当フォームに「現場住所（必須）」を出す。住所・工事日・時間・担当の条件を満たしたら一緒に保存し、担当別予定に移す。同じ担当の時間重複時はフォームにエラーを表示し、保存前の案件状態を維持する。 |
| 作業員の今日の案件（W01）と作業・報告（W02） | 割当日に該当する担当者へ表示する。登録時の住所または割当時に補完した住所を現場情報に表示する。任意メモがあれば作業員にも表示する。写真・報告の提出と管理者確認は[既存の報告仕様](../specs/reporting.md)を使う。 |

初期状態は工事「未手配」、報告「未提出」。工事時間の重複確認、提出後の割当制限、写真の要件は採用済みのルールを使う。根拠は[案件・予定仕様](../specs/scheduling.md)と[初回設計](../specs/prototype-design.md)。

### データ・保存

- 既存の案件データに登録内容を入れ、一意なIDと作成時刻を付ける。新規案件は作成時刻の降順、作成時刻を持たない既存案件は固定順で後ろに表示する。既存データの移行は不要。登録時点では担当・予定と報告は空のままとし、機器は1台扱いとする。
- [ADR-0001](../adr/0001-local-storage-and-role-preview.md)のIndexedDBと現在の案件ストアを使う。登録は新規挿入とし、既存案件を上書きしない。住所補完と日程・担当の設定は、既存の更新・競合確認に含めて同じトランザクションで確定する。完了後に共通の案件データから一覧と予定を描画する。[保存仕様](../specs/storage.md)
- 初期化の確認文に追加した案件も消えることを明記する。未入力の住所は「住所未入力」と表示する。保存方式と役割の境界はADR-0001で扱えるため、新規ADRの起案は不要と判断した。

### 代表画面の操作

[設計見本の入口](previews/T005/index.html)。開発サーバー起動後、ブラウザで `/docs/tasks/previews/T005/` を開く。[開発サーバーの起動手順](../README.md#開発確認環境)

1. 案件一覧の「新規案件を登録」を開き、元請けと現場名だけを入力して登録する。登録した案件が一覧の先頭に表示される。
2. 「予定・割当」から同じ案件を開き、現場住所を補う。今日の田中さんの枠を11:00〜13:00にして保存すると、未割当欄から担当別予定へ移る。元の9:00〜11:00を選ぶとサンプル案件と重複する。案件一覧からも工事状態を確認できる。
3. 「今日の案件」で田中さんとして案件を開き、補完した住所が作業・報告画面に表示されることを確認する。

見本は架空データを画面内のメモリで管理し、再読込で初期状態に戻る。確認対象は登録・住所補完・割当・作業員画面の導線。IndexedDB、保存失敗、初期化、管理者の報告確認は本実装で確認する。

### 保存失敗の再現

確認専用の新しいブラウザプロファイルでアプリを起動し、「案件一覧」が表示された後に開発者ツールのコンソールで実行する。現場名を「保存中断テスト」にして登録すると、挿入が成功した直後にトランザクションを中断する。フォームと入力が残り、成功表示が出ないことを確認する。`restoreRegistrationTest()` を実行してフォームを再送し、1件だけ追加されることを確認する。自動テストでは `node --test --test-name-pattern='rejected registration' tests/case-registration.test.mjs` で、中断後のDB内容と再試行を確認できる。

```js
(() => {
  const original = IDBObjectStore.prototype.add;
  IDBObjectStore.prototype.add = function (...args) {
    const request = original.apply(this, args);
    if (args[0].site === '保存中断テスト') {
      request.addEventListener('success', () => this.transaction.abort(), { once: true });
    }
    return request;
  };
  window.restoreRegistrationTest = () => { IDBObjectStore.prototype.add = original; };
})();
```
