# prepare-final-review

プロジェクトルートを基準にパスを解決し、AGENTS.md、docs/development-workflow.md、docs/tasks/README.md、対象作業記録を読む。手順から仕様や承認を新設・上書きしない。結果は対象作業記録へ残す。

## 手順

1. ①・②の承認範囲、P番号と結果、⑥の修正必須指摘の解消を確認する。未解消は⑥へ戻す。
2. 対象成果物の版、起動・アクセス・初期化方法、管理者と作業員の操作手順・期待結果を揃える。
3. 型・静的チェック・テスト・アプリとStorybookビルド・画面確認の結果を、実施環境とともに提示する。未実施と対象外には理由を付ける。
4. 仮置き・制限・改善候補、今回のADR、未確認のiPhone Safari写真操作・キーボード・保存／再読込等を明示する。PCの幅変更を実機確認としない。
5. 人間に⑧の確認資料を提示し、採用／修正／保留を対象版・日付・判断者・理由と記録する。返答前は最終確認待ちとする。
6. 修正は関連テストと影響範囲の確認、⑥・⑦を経て再提示する。仕様変更なら第9節に従う。
7. 本人の採用と実利用者のH01〜H03検証を区別し、後続の検証・担当・再確認条件を引き継ぐ。

成果物は最終確認資料、実際の採否、残課題と次の扱いとする。
