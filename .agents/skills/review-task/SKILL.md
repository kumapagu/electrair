# review-task

プロジェクトルートを基準にパスを解決し、AGENTS.md、docs/development-workflow.md、docs/tasks/README.md、対象作業記録を読む。手順から仕様や承認を新設・上書きしない。結果は対象作業記録へ残す。

## 手順

1. 別セッションで対象版、承認済み仕様、変更差分または比較元・対象ファイル、テスト、検証結果、採用済みADRを受け取る。実装者の説明だけで判断しない。
2. 仕様の充足と範囲逸脱、テストが失敗を検出するか、状態・保存・連続操作・再読込、UI・アクセシビリティを確認する。必要な検証を実行する。
3. 指摘には根拠、再現条件、影響、対象箇所を添え、修正必須／改善候補／要判断に分類する。未実施の検証も明示する。
4. 指摘を開発側へ渡し、修正後に対象と影響範囲を再検証する。人間判断が必要な仕様変更を修正名目で採用しない。
5. 修正必須の解消、ADRと実装の整合、確認結果の正確さを確かめて⑦へ渡す。新しい変更があればその版をレビュー対象にする。
6. 別セッションを使えない場合は自己レビューと記載し、独立レビュー未実施を最終確認資料に残す。独立した確認を行ったと偽らない。

成果物はレビュー方法・対象版・指摘一覧・修正と再検証結果・残課題とする。
