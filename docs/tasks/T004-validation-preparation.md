# T004 利用者検証に向けた完成版の準備

- 更新日 2026年11月24日（日本時間）
- 状態・現在工程 ①／人間確認待ち
- 対象成果物の版 作業定義案 v0.2。基点は `origin/main` の `e7b71af`、検証対象は案件登録を含む完成版
- 依存作業 [T002 初回プロトタイプ](T002-prototype.md)・[T003 開発フローの改善](T003-development-review-workflow.md)・[T005 案件登録と一覧への反映](T005-case-registration.md)
- 担当案 準備・記録はAI、検証時期・参加者の調整は依頼者、利用者検証は社長・作業員

## ① 作業定義

v0.1.0 に案件登録と一覧への反映を加えた完成版で、社長が案件を登録して日程・担当を決められるか（H01の前段とH01）、作業員が写真付き報告を提出できるか（H02）、社長が未報告と確認待ちを区別できるか（H03）を確かめられるようにする。[検証仮説と手順](../prototype-handoff.md#10-完成条件確認シナリオ)

### 推奨する順序と完了条件

| 順序 | 作業 | 完了条件・参照先 |
| --- | --- | --- |
| 1 | 検証対象版と当日の操作を準備する | T005の最終確認後に対象コミットを確定する。起動・アクセス、初期化、試験用の写真を用意する。架空データで「案件登録・一覧反映 → 割当・変更 → 写真と下書きの保存・復元 → 提出 → 管理者確認」を通して、当日の開始状態と手順を確認する。[T005の完成条件](T005-case-registration.md#完成条件案)・[T002の操作課題](T002-prototype.md)・[資料一覧の起動手順](../README.md#開発確認環境) |
| 2 | 観察項目とiPhoneの確認項目を準備する | H01〜H03の課題と、現行手順との比較、完遂・所要時間・支援・迷いを記録する欄をそろえる。iPhone Safariで確認する日時欄、写真の選択・撮影、キーボード、画面下部の提出操作、保存・再読込、管理者の報告確認をチェックリストにする。機種・OS・写真形式・対象版を記録できるようにする。[P05・P07・P09・P12・P13](../specs/acceptance.md)・[T002の実機残項目](T002-prototype.md#引継ぎ) |
| 3 | 最後の工程で利用者検証とiPhone Safari実機確認を行う | 完成版が決まった時点で依頼者が参加者と実施時期を調整する。実機動作とH01〜H03の観察結果を記録し、修正・再検証、次段階へ進む、または対象範囲を見直す、のいずれかを判断できる材料をそろえる。[利用者検証の順序](../prototype-handoff.md#11-プロトタイプ完成後の利用者検証) |

手順1と2が準備の完了条件。手順3は完成後の引継ぎ先で、実機動作と業務上の使いやすさはそれぞれ結果を残す。iPhone Safariの実機項目とH01〜H03は未実施。v0.1.0 の採用記録は [T002](T002-prototype.md) を参照する。

検索・絞込、複数台、施工チェック・追加作業、差し戻し・再提出、再訪問、「確認済み」からの戻しは後続候補。どの課題に効くかを利用者検証の結果から判断する。共有保存・実認証・LINE連携・本番インフラは今回の対象外。[段階2・3の候補](../prototype-handoff.md#3-プロトタイプの範囲)・[T002の最終レビュー](T002-prototype.md)

検証では [ADR-0001](../adr/0001-local-storage-and-role-preview.md) の架空データ、同一ブラウザ内のIndexedDB保存、疑似役割切替を使う。試験用の写真と実機へのアクセス方法は準備時に確かめる。参加者、端末、実施日は完成版が用意できた時点で調整する。
